# DMI v0.1.12 — Repository Repair & Core Withdrawal

**Type**: Repair / remediation release (breaking)
**Scope**: Specification catalogue, JSON Schemas, presentation surfaces,
documentation, and repository identity.

> **Status**: Prepared on the `repair/v0.1.12-concept-note-alignment`
> branch. This release note is written in advance of the PR merge. Dates
> and DOIs are deliberately left as placeholders until the PR merges and
> a versioned artifact is published.

---

## Summary

v0.1.12 is a **repair release**. It brings the repository into agreement
with the v0.1.12 methodology as documented in
[`docs/DMI_Methodology_Note.md`](../DMI_Methodology_Note.md) and the
concept note, and it removes advertised functionality that the code did
not actually implement.

The two operational specifications published under v0.1.12 are:

| Specification | Inflation input      | Slack input           |
|---------------|----------------------|-----------------------|
| **Baseline**  | CPI-U headline (all items) | **U-3** unemployment |
| **Slack-Plus** | CPI-U headline (all items) | **U-6** unemployment |

The previously advertised **Core** specification has been withdrawn.
See [`docs/repair/CORE_WITHDRAWAL.md`](../repair/CORE_WITHDRAWAL.md) and
[`docs/known-issues/CORE_OUTPUT_WITHDRAWAL.md`](../known-issues/CORE_OUTPUT_WITHDRAWAL.md)
for the full rationale and consumer-impact statement.

---

## Breaking changes

### 1. Core specification withdrawn

- **What**: No release published under v0.1.12 advertises a
  `spec_urls.core` entry in `releases.json` / `latest.json`.
  `specifications.json` no longer lists a `core` entry. The pipeline
  does not emit `dmi_release_*_core.json`,
  `dmi-*-core.csv`, or `dmi-*-core.parquet` artifacts.
- **Why**: The code that produced Core outputs did not implement a
  bona fide core-inflation calculation — it still used headline CPI
  inputs, then labelled the result "Core". Publishing that as a distinct
  specification was misleading. See
  [`docs/repair/CORE_WITHDRAWAL.md`](../repair/CORE_WITHDRAWAL.md).
- **Consumer impact**: Any downstream consumer that fetched
  `dmi_release_YYYY-MM_core.json` or the `spec_urls.core.*` fields must
  migrate to Baseline (or Slack-Plus, when broader labor slack is
  relevant). Historical `*_core.json` files that predate v0.1.12 are
  **not** part of the v0.1.12 published contract and will be withdrawn
  from the live site under a separate, explicit authorization.

### 2. JSON Schema major-version bumps

| Schema                                 | Old   | New   |
|----------------------------------------|-------|-------|
| `releases.schema.json`                 | 2.0.0 | **3.0.0** |
| `specifications.schema.json`           | 0.2.0 | **0.3.0** |

Under `releases.schema.json` 3.0.0:

- `spec_urls` accepts only `baseline` (required) and `slack_plus`
  (optional). A `core` key is rejected.
- Historical baseline-only entries (2025-12..2026-02) advertise only
  `baseline` and never carry `slack_plus`.

Under `specifications.schema.json` 0.3.0:

- `spec_id` is restricted to `baseline` and `slack_plus`. A `core`
  spec_id is rejected.

### 3. Withdrawn v0.1.9-era claims

The following v0.1.9-era claims are **not** part of the v0.1.12 published
contract:

- Bootstrap confidence intervals (never fully implemented; the
  `dmi_release_*_with_ci.json` companion is withdrawn).
- A validated 2011-2024 historical DMI time series (the historical
  fixture cannot be reproduced from the current pipeline without further
  work; it is not advertised in manifests).
- Point estimates for a specific reporting month
  (November 2024 in the v0.1.9 spec document): those numbers reflect a
  now-superseded methodology snapshot and should not be quoted as
  current v0.1.12 values.

The historical `DMI_v0.1.9_Spec.md` remains in the repository as an
archival record; `DMI_Methodology_Note.md` now carries a prominent
v0.1.12 status banner flagging superseded content.

## Added

### Baseline / Slack-Plus identity + enforcement

For every group `g`:

```
DMI_slackplus(g) − DMI_baseline(g) = (1 − α) × scale_factor × (U6 − U3)
                                   = U6 − U3   (α = 0.5, scale = 2)
```

Enforced by `tests/test_baseline_slack_plus_identity.py`:

- Per-group DMI shift equals `U6 − U3` for every paired release.
- All paired releases share `α = 0.5` and `scale_factor = 2.0`.
- At least one Baseline / Slack-Plus pair is present.
- Symbolic tests confirm the identity fails cleanly if `α` diverges.

### Manifest coherence enforcement

`tests/test_specifications_manifest_coherence.py` covers:

- Detection of `release_json` period mismatch.
- Detection of stale `reference_period`.
- Detection of stale `slack` value copy-forward.
- Freshly built manifest passes coherence.
- The writer reads `slack` from the referenced per-release JSON, not a
  stale cache.

### Schema validation regression tests

`tests/test_schema_validation.py` (new) covers:

- `releases.json` / `latest.json` validate against
  `releases.schema.json` 3.0.0.
- No release entry advertises `spec_urls.core`.
- Baseline-only historical entries have no `slack_plus`.
- `specifications.json` validates against 0.3.0 and contains no `core`
  `spec_id`.
- Every current `dmi_release_YYYY-MM*.json` validates against
  `dmi_output.schema.json`.

### GitHub Actions guardrails

- `monthly_dmi.yml`: no Core compute step; QA + coherence gates before
  deploy; sanity-check that `releases.json`/`latest.json` metrics agree
  with the raw baseline release.
- `deploy_web_dashboard.yml`: guard that fails the deploy if
  `releases.json` advertises any `spec_urls.core` entry.
- `deploy_wp_plugins.yml`: guard comment enforcing the no-core rule for
  plugin releases.
